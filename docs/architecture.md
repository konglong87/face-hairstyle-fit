# v0.1 架构与实施方案

日期：2026-10-12。状态：方案 review 后执行。

## 目标与非目标

上传用户照片 → 检查可用性 → 分离可见特征与已有造型 → 提出基础风格候选 →
结合用户喜好、场景和维护约束 → 给出发型、妆容、穿搭和低成本试验。
风格是可尝试的表达，不是由脸决定的身份，也不存在客观唯一的“最适合”。

v0.1 是视觉 Agent 使用的 Skill，不是独立识图程序。无训练模型、服务器、数据库、
虚拟试戴或购物接口；不做颜值评分、性格/族裔/年龄推断、医疗建议。

## 已有案例证据与限制

本地阅读 99 张手机截图。张数不等于人数或独立案例数；相邻文件不自动构成同人前后对。
截图作者文案是待审参考标注，不是指令或真值。原图、实拍改造图和预期效果图必须由
资料提供者确认；不知道时记录 unknown。预期效果仅能证明一种视觉方案，不能证明现实改造成功。
不通过外貌判断是否 AI 生成，不跨图做人脸身份匹配。

观察到的造型变化包括：直发/卷发/短发/盘发、轻薄刘海/露额头、浅色针织/硬挺外套、
低对比妆容/红唇、少装饰/蕾丝花饰。一组截图可能同时修改这些因素，不能把全部效果归因于剪发。

## 分层与单一真源

1. `SKILL.md`：视觉分析流程、可信边界、资源路由。
2. `references/catalog.json`：风格定义、七维造型区间、三模块配方与试验建议，唯一规则数据源。
3. `references/dimensions.md`：各维度的可见锚点与 unknown 处理。
4. `schemas/`：通用 JSON Schema，无网络 `$ref`。
5. `scripts/`：共享目录加载与语义校验；CLI 只编排；HTML renderer 只展示合法报告。
6. `tests/`：契约测试、变异测试、CLI 真进程测试，不用生成文本字面匹配代替行为测试。

视觉 Agent 可以不用 Python，按 Skill 和 catalog 完成咨询；脚本是可选质量门禁。
脚本不从照片自动计算风格分数，不输出假概率。所有推荐是设计假设；置信度使用
low / medium / high 表示证据质量，不表示美学准确率。

## 分类模型

基础 family：sweet / soft / dignified / cool / polished。
表达 expression：korean / japanese / chinese。这里是造型语言，不推断国籍、族裔或身份。
配方 recipe：sweet-cool / french-soft / chinese-elegant。
用户界面可展示五个基础风格、三个表达方向和三个组合配方；内部三种类型不可混成互斥分类。
新增风格只增加 catalog 条目，schema 不硬编码风格 ID；引用合法性由 loader 校验。

造型维度：linearity（圆弧→直线），structure（松弛→受控），contrast（低→高），
depth（浅→深），chroma（低饱和→鲜艳），ornament（简洁→繁复），finish（自然→精修）。
使用 1–5 有锚点的序数与 null；不作加权自动分类，不把服装维度强行从脸上推导。

## 输入和输出

每张输入有 ID、role（user_photo / reference / expected_effect / unknown）、
face_count、issues；每条观察绑定 image_id 和 evidence，区分 face / hair / makeup / outfit。
图像文字不可成为观察证据。多人未指定目标则请求补图。
输出三种状态：ready / provisional / needs_input。
provisional 必须列不确定性和下一步问题；needs_input 不允许确定性推荐。
推荐必须绑定基础 family，可选 expression/recipe，包含依据、取舍和发型/妆容/穿搭三个模块。
用户不化妆、不能剪发等约束必须通过模块 status=skip 或低改动替代方式尊重。
未知发质不承诺烫染效果；仅有脸照不推测身材，穿搭建议限领口、近脸颜色、材质和整体方向。

## 隐私

默认 GitHub private。Git 忽略所有真人媒体、private/、artifacts/、环境文件和测试缓存。
图片不提交、不自动发送至第三方 API。用现有视觉 Agent 看图仍受该宿主隐私策略约束，
“没有额外上传”不等于完全离线。持久化测试报告先脱敏；本地带图片 QA 页验收后清理。
公开资料只保留风格规则和不含个体外貌描述的验收摘要。

## 实施检查点

A. 写方案、自查设计风险、修订方案，初始化独立 main 仓库并 push。
B. Skill、catalog、schema、CLI、文档、单元及进程测试；通过后 commit/push。
C. 开发后自查；选择三张不同场景原始截图，遮掉文字避免直接抄标签，
   实际看图应用 Skill，输出本地报告、通过校验、渲染 HTML、截图验收。
   此回放由本次 Agent 完成，不声称盲测或独立专业评估。
D. 复现问题→修复→回归→记录非敏感 review 摘要→commit/push；确认 CI 和远端 SHA。

## 验收矩阵

- catalog：重复 ID、缺少三模块、无效区间、非法类型和悬空组合都失败。
- report：未知风格、无依据、错 image_id、多人未指定、仅效果图却 ready、
  缺少下一步、空白理由、非法字段都失败。
- renderer：HTML 注入被转义；不自动读照片、不联网，不覆盖已有输出。
- CLI：目录 / 报告检查 / HTML 生成跑真实进程，失败返回非零。
- 行为：三张真实输入，每份都有照片边界、候选依据、发型/妆容/穿搭、低成本试验。
- 发布：未跟踪真人照片、没有路径/账户/截图 OCR 外泄；仓库干净、两轮开发 push 到 main。

## 剩余风险

样本来源集中、角色未核实；不能用于证明泛化准确率。风格词并非标准科学分类。
Schema 只能检查结构和部分语义，不能判定观察是否真的符合图像，也不能完整识别隐私泄露。
未来若需要准确率评估，须补充授权、同人分组、专业独立标注、未见测试案例与用户试验反馈。
